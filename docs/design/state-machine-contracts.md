# State-machine contracts

Audit baseline: [main 19d63dfc](https://github.com/cenetex/cosyworld/commit/19d63dfcd348be183d0e491e733adc7c6edc1372), package 1.2.127, shared rules 129, 2026-11-09.

## Decision

Keep the existing authority boundaries. Make their transitions, interruption rules and tests discoverable before extracting controllers. Do not introduce a global state-machine framework or flatten independent facts into one phase. The game already has a transactional `play` boundary; dialogue, authoring and shared speech already fence much asynchronous work well. Extend those patterns where evidence shows a gap.

This improves UX by preserving progress and preventing stale effects, DX by making ownership and test seams obvious, and AX by giving an agent canonical actions, retry identity and observable outcomes. AX here means agent experience, not accessibility; existing reduced-motion, focus and screen-reader behavior must also remain intact.

This is a source inventory of 70 machine families, including explicit machines that bound implicit ones. A family can have many authored instances. It is not a claim that every runtime interleaving or historical save has been exercised. Shipping card rules/UI and their services are primary; retained compatibility services are marked separately. No production journal or private user save was inspected. The inactive room-fuel helper and pending lamp rules130 are not shipping behavior at this baseline.

## How to read the inventory

Game/UI source paths are relative to `v2/card-game/`; Rust paths are relative to `v2/orchestrator-rust/src/`. Test names without extensions refer to `test/<name>.test.mjs`; `smoke-*` names refer to `v2/scripts/<name>.mjs`. Ranges identify baseline code, not permanent line numbers. Coverage entries identify existing checks, not claims that they all passed in this audit.

## Prioritized findings and proof required

1. **Fixed here, U14: transition ownership.** Two deterministic regressions fail on baseline: show A → immediate hide → show B → decode B → decode A starts a second obsolete animation; fulfilled hide → immediate show → old completion hides the current layer. A unique transition object now fences both decode and finish. Four tests cover those failures plus interrupted show, repeated intent, decode failure and ordinary hide. No new UI, styles, rules, save schema or released bundle changes.
2. **Next, S08: concurrent voice cache misses.** Source interleaving shows two authorized misses can synthesize different audio, `INSERT OR IGNORE` stores one, and each caller returns its own bytes. Existing test is sequential. Add a barrier-controlled two-request provider test; then bounded keyed single-flight, cache recheck and durable-winner return. Preserve authorization before cache access. Not runtime-reproduced in this audit.
3. **Next, G14/P01: off-path legacy journey.** Executed isolated helper reproduction: agreed journey missing progress + actor off path → `step: -1` from `indexOf`, rejected by `validJourneyProgress`. Existing test migrates on path then detours. Add a full old-save decode fixture before choosing a migration fallback; retain agreement and do not invent completed progress. No affected production save established.
4. **Next, U15/U22: reset ownership.** `sleepView.stop()` exists but app reset/storage adoption does not call it. Test reset while dreaming/quest-dealing, old completion after world replacement and tab hiding through sleep beats. Clearing timers alone is insufficient if seen/wake identity survives. Risk from source, not browser-reproduced.
5. **Then, U16/U17/U21/U01: interruption boundaries.** Reverse response order across menu close/reopen; old settings rejection after reopen; real Back/Forward BFCache restoration; local setup/import failure while body is inert. Add explicit operation ownership only after failing cases establish intended behavior.
6. **Then, S14/S15: stale leased workers.** Claim A, expire/reclaim B, finish/fail A; B's status, attempt and reservation must remain unchanged. Current media finish fences only id+running; actor failure writers sometimes fence only id. Fix with owner/attempt checks after reproducible tests, not broad queue rewrite.
7. **Then, P03/S17: durable failure injection.** Queue newer save during failing/conflicting write; restart at each acknowledgement boundary; fail event-head read before compaction. Preserve every recovery copy and distinguish browser save, disk acknowledgement and conflict. Snapshot event-head failure currently falls through while journal durability failure fails closed; reachability needs proof.

## Reusable contract and rollout

For every new or changed owner, record: canonical state and derived facts; accepted events; guards; durable commit point; operation identity; side effects; cancellation/suspension/reset; recovery/terminal outcomes; test seam; observable status. Keep it beside the owner, linked here. Prefer a small pure reducer/selector when states are genuinely exclusive; retain orthogonal facts otherwise.

Use this sequence test matrix: happy path; repeated event; stale revision; older success after newer success; older failure after newer success; cancel/close/reset before each await; hide/show and BFCache; persistence failure before/after commit; restart/replay; duplicate idempotency key; timeout with unknown result. A thrown transport error is not evidence that a command did not commit.

For human and agent tooling, derive a read-only bounded status from authoritative state: phase, owner/run, revision or attempt, pending operation key, permitted next actions, retryability and last outcome. Do not create another writable state store or log private dialogue/save payloads. Agents use returned legal action keys/current revision and preserve the original request key while resolving uncertainty. A visible label alone is not authority.

Roll out one boundary per small PR: failing characterization → narrow change → independent review → affected unit/sequence tests → desktop and phone browser paths → exact-head hosted checks. Keep existing card/bar/context-button UI. Engine refactors require the existing equivalence, released-bundle, native agreement and journal replay gates, plus a new rules version only where required. Do not combine this audit with pending lamp activation, schema migration, deployment or a global controller rewrite.

This first patch changes only presentation ownership and tests. It cannot establish that the whole application is regression-free; keep the PR draft until required browser and hosted gates are verified.
