# Shared systems and exceptions

Reviewed 2026-11-27. This audit covers the playable card table, mounted packs, shared worlds, the desktop runtime and service integrations. The Void 003 repair is included in the baseline. Each entry points to the code that governs the exception and records what to preserve or consolidate.

## Confirmed defects to fix next

1. **A later quest stage inherits knowledge of an earlier stage.** RATi’s Red Beanie, Raven Figurine and glass lays target the same room. The live quest comparison distinguishes those stages. The learned fact key uses only owner and destination. In an in-memory reproduction, learning the Beanie stage made the Raven stage appear learned, while the stored fact still described the Beanie and a repeat Talk could not refresh it. Give authored stages stable IDs and use them in quest facts, card state and learning checks. Retain ambiguous historical facts as evidence of the old stage and unlock a current stage only when its evidence matches. [Authored stages](../../v2/content/ratiradio/card-world.json#L65) · [Fact identity](../../v2/card-game/knowledge.mjs#L16) · [Live quest comparison](../../v2/card-game/want.mjs#L118) · [Learning](../../v2/card-game/talk-quest.mjs#L103)
2. **Someone else’s branch choice can reach an avatar’s narration prompt before they learn it.** A Vale with empty learned facts who entered Wine-Dark Harbor received an “Established account” fact about an earlier traveler giving Helen’s Account Tablet to Myrto. An in-memory fixture reproduced it using the committed Greek branch receipt. Keep the canonical choice available to simulation and scenery. Expose it to an avatar’s prompt through witnessed, heard or read evidence, or through a present observation. Test a second player arriving after the choice. [Branch facts](../../v2/card-game/pack-registry.mjs#L986) · [Prompt facts](../../v2/card-game/narrative.mjs#L475) · [Evidence model](books.md)
3. **Returning to `/` can miss the last shared world after an account reset.** The entry module reads the raw `cosyworld.playing` key, whereas the table writes the account-scoped key after reset. A fixture ran the real startup and reset code with stubbed browser imports. Before reset, `/` redirected to the saved world. After reset, a valid scoped receipt was ignored and the local table opened. Use the account storage adapter for startup and title reads. Cover resume after reset alongside blocked storage and the members lock. [Entry](../../v2/card-game/entry.mjs#L10) · [Account storage and reset](../../v2/card-game/account-reset-storage.mjs#L14) · [Existing reset tests](../../test/card-account-reset-storage.test.mjs)

## Design direction

- **One path from a play to a scene.** The rules commit the action and choose the cast. A speaker policy chooses the model and whether it can fall back. The narrator sequences the exchange and records what each voice produced. The browser renders that result. Personal and shared play can establish authority differently and still use the same scene contract.
- **Stable IDs carry meaning.** Store the actor, quest stage, event type, evidence and outcome in records, then render words from those records. Use a versioned reader for older saves whose only evidence is a sentence or an ordinal. Keep recorded lines, card actions and receipts independently replayable.
- **Pack data owns fiction and parameters.** Put rooms, character and token relationships, opening facts, art roles and the parameters for reusable capabilities in validated pack content. Deterministic code owns movement, custody, authority and evidence. Keep provider routes, budgets and authenticated entitlements in server policy. A generated manifest can connect the public resident and its reviewed provider binding.
- **Recovery preserves what already happened.** A model or audio failure leaves the committed play intact. A failed save keeps the last durable copy available. A revoked entitlement evicts private assets. On new exceptions, record the trigger, authority, player-visible result, test and any condition for retiring compatibility.

## Suggested sequence

Fix the three reproduced defects separately so their migrations and regressions stay reviewable. Then add typed scene and identity outcomes, starting with a Void introduction and Listener reading. Use that contract to consolidate narration recovery and caption presentation. A validated Void encounter manifest can follow, with a Station admission descriptor or Boardy capability as the first test of bringing the same approach to world rules.
