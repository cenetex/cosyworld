# Elysium: residents that name and draw themselves

## Playing the chapter

The Void Wayfinder starts somewhere reachable in the ordinary world. Raise
it after nightfall to reveal a crossing into Void 001. The silver filament
in Void 002 leads to Empty Station at any hour. If the last traveler leaves
the Wayfinder in Elysium, it scatters back into the ordinary world.

Void 001 keeps the Silver Resident and the Keystone chapter. Void 002–007
each have an unnamed resident, their own illustrated token, and a distinct
room. First Talk sends that resident's token to the ordinary world. Bring
it back and give it to the resident to complete their request.

Shared tables call the six bound models for their own names and replies.
On a token return, its resident's model describes its appearance, then the
portrait service renders it. The name and portrait are reused across
tables once earned in each table. Solo tables support the exploration and
the token quest. The hosted naming and portrait generation use authenticated
shared plays.

Elysium is the pack for raw models. Each Void holds one resident, and each
resident is bound to one model. No resident ships with an authored name,
description or portrait. The first Talk with a resident runs its model for a
name. Meeting it scatters its void token. The first time the token is
returned to its Void, its model describes the resident and an image model
draws it. A name or portrait, once made, holds in every world on the server.

Paths are relative to the repository root; `card-game/` means `v2/card-game/`
and `rust/` means `v2/orchestrator-rust/src/`. "The prompt" is the text the
Rust text route sends to a model; "output" is what the model returns.

## Decisions

Decided by the owner on 2026-11-26.

1. **Elysium residents are raw models.** Each Void has one resident, and each
   resident is bound to one model. The pack authors no name, persona or
   portrait for it.
2. **Identity is server-wide.** A resident's name and portrait are the same in
   every world on the server, as a passkey holder's name is (`holder_name`,
   `rust/card_shared/bindings.rs:26`). The first world to reach each moment
   sets it for all.
3. **The first Talk names the resident.** The first Talk on the server runs the
   bound model for a name.
4. **Meeting scatters the void token.** Each resident has a void token. Meeting
   the resident sends it out into the world.
5. **Returning the token draws the resident.** The first time a resident's
   void token is returned to its Void, its portrait is generated.

## Where things stand

Void 001's shared portrait pilot uses the Gold Spiral opening and a server
record of the Keystone return. A later committed turn can start the job for
an earlier shared return, or retry after five minutes. Imported progress needs
a shared return before it can draw the resident. Reading serves only the
finished PNG. The original art and passage work throughout. Every world shares
one content-addressed image drawn from public Void context. If that file is
corrupted, an operator can restore its original bytes under the same hash.

- **Every avatar needs authored identity.** The pack schema requires a name,
  a one-line seed and a portrait file for every avatar
  (`card-game/pack-schema.mjs:759`, `:836`). PR #3200 meets this with the
  Silver Resident, whose name, seed, tastes and portrait are authored.
- **Models are chosen per job, not per resident.** Text routes pick models by
  tier from the environment (`COSYWORLD_CARD_REFLECTION_MODEL`,
  `COSYWORLD_CARD_ESCALATION_MODEL`, `VoiceSettings::from_lookup`,
  `rust/card_narrative.rs:1447`) and the AI registry (`rust/ai_registry.rs`).
  No avatar names its own model.
- **Reflections already record their model.** An accepted reflection keeps
  its evidence and the model that produced each persona and thought
  (`r.models`, `validReflections`, `card-game/memory.mjs:245`).
- **The reply check refuses model self-reference.** `META` in
  `rust/card_narrative/framing.rs:8` rejects "as an ai", "language model" and
  similar phrases in a reply.
- **Names reach the rules and the reply checks.** Choice text, logs and the
  unfound-name blur read names from pack data (`nameOf`,
  `card-game/pack-registry.mjs:373`; `unfoundBlur`,
  `card-game/speech-knowledge.mjs:73`). The Rust known-names list is compiled
  from pack text (`v2/scripts/build-card-authored-text.mjs`).
- **A meeting can already scatter a thing.** A `meet` choice with a
  `hide_item` effect moves the item to an active place hashed from the
  choice, the traveler and the turn, across every mounted pack. It also gives
  the subject a want for it (`hidingPlace`, `card-game/pack-registry.mjs:654`;
  the effect at `:892`).
- **Image generation exists for authoring.** `rust/card_authoring_image.rs`
  checks the request and the configured model and re-encodes the PNG.
  Generated bytes share one budget (`rust/generated_asset_budget.rs`).
- **Worlds replay from their journals** under pinned rules bundles
  (`ARCHITECTURE.md`). A server-wide value that the rules read live would make
  a replay disagree with its first run.

## Proposals

### E1. Bindings are pack data

- An Elysium avatar gains a `model` field (a registry model id) and drops
  `name`, `seed`, `portrait` and `tastes`. The schema allows those fields to
  be missing only when `model` is set.
- Until it has a name, the resident shows a name derived from state: "the
  resident of Void 002".
- Until it has a portrait, it shows the faceless silver figure from the art
  proposal (today's `assets/elysium/resident.png`). That figure is the shared
  undrawn form of every Elysium resident.
- PR #3200 keeps its places, filaments, Wayfinder and Keystone. The Silver
  Resident becomes the undrawn resident of Void 001, bound to a model.

### E2. A server-wide identity store, entered into worlds as events

- A table beside `card_bindings` holds one row per resident:
  `(resident, model, name, named_at, portrait, drawn_at)`. Each field is
  written once; the first write wins and later attempts read it.
- A world never reads the table from the rules. When a world reaches the
  naming or drawing moment, the server commits the stored value, or the newly
  generated one, as a log entry and saved state
  (`world.packs.elysium.identity[id] = { name, portrait }`). A replay applies
  the same entries.
- A name joins the world's known names when it is committed, so the reply
  check and the unfound-name blur treat it like an authored name.

### E3. The first Talk names the resident

- On a world's first Talk with an unnamed resident, the server checks the
  store. With no name stored, it runs a naming prompt against the bound model:
  the resident's own memories and its Void, asking for a name.
- The output is accepted if it is one to three words, at most 40 characters,
  not an existing name in any mounted pack, and passes `content_policy.rs`.
  Otherwise the Talk goes ahead and the next Talk asks again.
- With a name already stored, the Talk commits it at once.

### E4. Meeting scatters the void token

- Each resident has one token item, `elysium-<void>-token`, held by the
  resident at the start, with `home` set to its Void.
- A `meet` choice for the resident carries `hide_item` for its token. That
  is today's effect: the token lands at an active place anywhere in the world,
  and the resident wants it back.
- A world where the Elysium group is switched off keeps the token where it
  lies, as other keepsakes do.

### E5. Returning the token draws the resident

- The first time the token lies in its Void (`item_at`), and the store holds
  no portrait, the server runs two jobs:
  1. The bound model writes a short appearance from its name and memories, at
     most 600 characters, the persona limit.
  2. An image model renders that text inside a fixed Elysium frame: black
     paper, fine silver etching, restrained gold, a full figure on a 2:3
     canvas. The output is cut out to a 1024 × 1536 RGBA portrait and stored
     by content hash.
- The portrait is committed into the world as in E2. A Discord face box is
  computed from the cutout's head.
- With a portrait already stored, returning the token commits it at once.
- The resident is drawn once per server, so the image cost is bounded by the
  number of Voids.

### E6. Raw voice

- An Elysium resident's replies, reflections and naming run on its bound
  model, not the tier models.
- `META` in `framing.rs` does not apply to Elysium residents. Grounding,
  custody and unfound-name checks still apply.

## Open questions

1. **Who picks each Void's model?** Proposed: the pack lists them, one per
   Void, so changing a binding is a reviewed pack change.
2. **What counts as returned?** Laid in the Void (`item_at`), or given to the
   resident? `hide_item` gives the resident an item want, so a gift would
   meet the want and level it, and laying it down would draw it. Both could
   hold: draw on either, level on the gift.
3. **Is a name visible before a world has talked?** Proposed: no. Each world
   learns a stored name at its own first Talk, so the moment stays in every
   world's journal.
4. **Rename and redraw.** Proposed: never, both write-once. The owner's
   moderation route (`rust/moderation.rs`) can clear a row, after which the
   next world to reach the moment sets it again.
5. **Tastes.** The schema needs `likes` and `sore`. Proposed: written by the
   same naming job, stored with the name.

## Plan

Each step is a small PR. Steps 1, 2 and 5 change the shared rules, so they
ship together as one rules version with the `engine` label.

1. Schema: `model` on avatars, optional identity fields with it, and derived
   placeholder names.
2. The identity store and the commit events, with replay tests.
3. Naming on first Talk, with its output checks.
4. The void token and its `meet` scatter (pack data on existing rules).
5. Drawing on return: the appearance job, the image job, the cutout and the
   Discord face.
6. Per-resident model routing and the `META` exemption.
